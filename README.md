# Luobo - 最佳 Navidrome 客户端

**Luobo**（萝卜）是基于 [Musly](https://github.com/dddevid/Musly) 二次开发的 Navidrome / Subsonic 音乐播放客户端，使用 Flutter 构建，支持 Android 和 iOS。**相比原版 Musly 增加了车载模式、听歌报告、AI 歌单等特色功能，以及大规模国际化适配。**

---

## 🎵 Musly 原生功能

### 核心播放与服务器支持

- **多服务器兼容** — 支持 Navidrome、Subsonic、Airsonic、Gonic、Emby、Jellyfin
- **高品质音乐流** — 智能转码（WiFi/移动网络自适应比特率切换）、ReplayGain、无缝播放（Gapless Playback）
- **音频增强** — 10 波段均衡器、淡入淡出、音高控制、播放速度调节、Dolby Atmos 支持

### 播放器与歌词

- **Apple Music 风格界面** — 现代化设计，暗色/亮色主题自动切换
- **同步歌词显示** — 实时歌词同步、桌面全屏歌词、iOS 动态岛歌词、Android 锁屏歌词、Windows 通知栏歌词
- **播放控制** — 随机播放、循环播放（列表/单曲）、播放队列管理、手势快速切歌

### 离线与本地

- **离线下载** — 并行下载、批量下载、离线播放切换自动降级
- **本地音乐库** — 自动扫描本地文件、与服务器库无缝融合

### 推荐与内容发现

- **智能推荐** — 基于听歌历史的个性化推荐、For You 列表
- **网络电台** — 服务器电台流媒体
- **浏览功能** — 按流派、艺术家、专辑、时间线浏览

### 高级特性

- **多服务器档案** — 快速切换不同服务器账户
- **主题自定义** — 完整的 Now Playing 主题编辑器（5 个编辑 Tab、背景/圆盘/文字/控制/动画）、主题导入导出
- **Android Auto** — 车载系统原生集成
- **Chromecast / UPnP** — 投屏到电视
- **Discord 状态** — 正在播放的歌曲显示在 Discord
- **Jukebox 模式** — 服务器端远程播放控制
- **自动更新** — GitHub 版本检查和应用更新

### 平台覆盖

- 📱 Android 6.0+
- 🍎 iOS 15.0+  
- 🖥️ Windows 10+
- 🐧 Linux（GTK）
- 🍎 macOS 11+

## 🚀 Luobo 差异化功能

### 📍 车载模式（Car Mode）— 安全驾驶专用界面

**设计理念：** 简化操作、快速获取信息、最小化分心

#### 核心功能

1. **3 行大字歌词显示**
   - 当前行 + 前后各 1 行歌词并行显示
   - 实时同步（毫秒级精度），随音乐进度自动滚动
   - 字体大小自适应，可在驾驶中清晰看到
   - 自动获取本地缓存或服务器歌词，无缓存时显示"暂无歌词"

2. **环形进度条 + 时间显示**
   - 圆形播放进度指示（取代线性进度条）
   - 中心显示已播放/剩余时间（如 02:34 / 04:15）
   - 动画流畅，易于驾驶时快速扫一眼了解进度

3. **屏幕常亮（WakeLock）**
   - 进入车载模式自动启用屏幕常亮
   - 防止手机息屏，无需频繁亮屏
   - 退出模式自动恢复系统息屏策略

4. **下滑手势返回**
   - 支持从上往下拖动返回到播放器
   - 手势位移超过 150px 触发返回
   - 动画反馈：页面随手势缩小、圆角增大、透明度降低
   - 触感反馈（Haptic）确认返回操作

#### 技术实现细节
- 使用 `WakelockPlus` 控制屏幕常亮
- 手势识别：`GestureDetector` + `Drag` 事件处理
- 歌词实时渲染：基于 `flutter_lyric` 包的同步显示
- 本地/远程歌词优先级：先查本地缓存（`OfflineService`），再调用服务器 API

**UI 优化：**
- 全屏沉浸式设计，状态栏隐藏
- 深色背景（减少驾驶时的眼睛疲劳）
- 触摸区域优化（按钮足够大，易点击）

**使用场景：**
- 🚗 驾驶时快速查看歌词、了解播放进度
- 🛵 摩托车、自行车骑行时安全操控
- 📱 健身房跑步机上的辅助显示

### 📊 听歌报告（Listening Report）— 个人音乐年鉴

**数据来源：** 基于 `RecommendationService` 的历史记录系统，实时追踪每首歌的播放、跳过、单曲循环等行为

#### 12 大分析维度

1. **概览统计（Overview Section）**
   - 总听歌时长（小时/分钟）
   - 播放次数（总计）
   - 歌手总数、歌曲总数
   - 快速卡片展示，便于一览无余

2. **完播率分析（Completion Rate）**
   - 计算：`总播放数 / 完整播放数`
   - 百分比 + 个性化评语（系统自动生成）
   - 评语示例：
     - 95%-100% → "你是个忠实粉，每首歌都能认真听完"
     - 70%-94% → "大多数歌曲都能完整收听"
     - <50% → "你更喜欢'点歌机'模式，经常挑选最爱的歌"

3. **时段偏好（Time Period Insights）**
   - 分时段分析：早晨/中午/下午/晚上/深夜
   - 显示每个时段的热门流派、最常听的歌手
   - 热力图可视化：某个时段偏爱哪类音乐
   - 数据来源：每次播放时记录的时间戳

4. **排行榜（Ranking Section）**
   - **Top 10 歌曲** — 播放次数最多的歌
   - **Top 10 歌手** — 听歌次数最多的艺术家
   - **跳过榜** — 最常被跳过的歌（播放 <10% 就跳过）
   - 每个榜单显示排名、歌曲/歌手名、播放次数或跳过次数

5. **单曲循环记录（Loop Kings）**
   - 检测单曲循环行为：同一首歌在短时间内连续播放多次
   - 显示最喜欢"反复听"的歌曲
   - 统计循环次数、最近一次循环时间

6. **流派分布（Genre Distribution）**
   - 饼图/柱状图展示流派占比
   - **中英文自动归一化**：
     - Pop、C-Pop、国语流行 → 流行（统一为"流行"）
     - Rock、摇滚 → 摇滚
     - Hip Hop、说唱 → 说唱
   - 支持自定义流派别名配置

7. **新发现（New Discoveries）**
   - 算法检测：之前很少听，最近频繁播放的歌
   - 时间窗口：过去 7 天内新增的高频歌
   - 帮助用户发现自己最近新喜欢的音乐

8. **老朋友（Old Friends）**
   - 反向算法：陪伴时间最长的歌手
   - 计算：单位时间内总听歌时长最多
   - 展示与该歌手"相识"的时间跨度

9. **周末 vs 工作日对比（Weekend Insight）**
   - 两组对标数据：
     - 周末听歌时长 vs 工作日听歌时长
     - 周末喜欢的流派类型 vs 工作日
     - 周末听歌时间分布 vs 工作日
   - 可视化展示：左右对比卡片

10. **能量曲线（Energy Curve）**
    - X 轴：时间段（0-23 点）
    - Y 轴：该时段歌曲的平均节奏能量值
    - 根据歌曲流派推估能量等级（摇滚/电音 = 高能量，民谣/古典 = 低能量）
    - 曲线图展示一天内的音乐"节奏"变化

11. **歌荒预警（Drought Warning）**
    - 检测：用户的常听歌曲库存
    - 逻辑：如果 Top 100 歌曲的累计播放次数 / 总播放次数 > 80%
    - 提示：可能需要新歌曲或新歌手，避免听觉疲劳

12. **最长单曲循环（Longest Loop）**
    - 统计：某首歌被反复循环的最长纪录
    - 显示：歌曲名、循环次数、循环时长
    - 找出"你最钟爱的歌"

#### 数据源与更新
- **实时追踪**：每次播放、跳过、点赞、评分都被 `RecommendationService` 记录
- **存储**：SQLite 数据库（替代了旧版 JSON 缓存，避免大库 OOM）
- **更新频率**：后台自动更新，新增播放记录后实时显示

**使用场景：**
- 🎉 年终回顾自己的听歌喜好
- 📈 发现音乐品味的变化趋势
- 💭 了解自己的听歌规律（什么时间听什么歌）
- 🎵 找出被遗忘的好歌（"老朋友"视图）

### 🤖 AI 歌单系统（AI Playlist System）— 智能歌单生成 + 知识库共享

**核心价值：** 用 AI 替代手动策划歌单，降低 API 成本，支持团队知识库共享

#### Part 1：AI 歌单生成（AI Playlist Generation）

**工作流：**
1. 用户在「AI 歌单」设置 Tab 配置 AI 连接
2. 系统记录听歌历史、流派偏好、跳过模式等特征
3. 调用 AI API，输入用户听歌特征和主题（如"治愈向"、"高能量"）
4. AI 生成主题化歌单
5. 歌单自动保存到本地库

**支持的 AI 模型：**
- ✅ DeepSeek（默认，免费额度充足）— API Key 配置示例
- ✅ OpenAI（GPT-4、GPT-4o）— 企业级准确度
- ✅ Kimi（文心 Kimi）— 中文理解最佳
- ✅ 阿里通义（Qwen）— 国内部署友好
- ✅ 自定义 API 服务器 — 支持私有大模型服务

**配置参数：**
```
AI API Key:     [输入框] （从对应 AI 平台获取）
Base URL:       https://api.deepseek.com （默认）
Model:          deepseek-v4-flash（下拉选择）
```

**参数验证：**
- ✔ 调用前验证 API Key 有效性
- ✔ 测试连接（试发送小请求）
- ✔ 错误反馈：网络错误、认证失败、余额不足等

#### Part 2：歌曲知识库系统（Song Knowledge Cache）

**问题背景：**
- 原始 Musly：没有知识库，每次 AI 推荐都需要重新发送全部歌曲特征
- **成本高**：大库的 API 调用费用很高
- **低效**：重复调用浪费资源

**Luobo 解决方案 — 离线知识库：**

1. **批量生成知识库**
   - 一次性为整个音乐库生成特征向量（Embedding）
   - 每首歌生成：歌名、歌手、流派、节奏特征的向量表示
   - 存储到本地 SQLite（`song_knowledge_cache` 表）

2. **断点续传（Resume on Network Failure）**
   - 生成过程中网络中断？不需要重新开始
   - 系统自动记录最后一个已处理的歌曲 ID
   - 恢复后从中断点继续处理后续歌曲
   - 进度条显示：已处理 123 / 500

3. **增量更新（Incremental Update）**
   - 新增歌曲时，只需为新歌生成知识库条目
   - 不重复处理已有歌曲
   - 定期检测：`本地歌曲总数 vs 知识库条目数`，差异则触发增量更新
   - 节省 API 调用成本

4. **知识库导出/导入（Export & Import）**
   - **导出**：将本地知识库导出为 JSON 文件
     ```json
     {
       "timestamp": "2026-07-31T20:00:00Z",
       "version": "1.0",
       "entries": [
         {
           "songId": "123",
           "title": "周杰伦 - 青花瓷",
           "embedding": [...],
           "genre": "流行",
           "energy": 0.65
         }
       ]
     }
     ```
   - **导入**：加载其他设备导出的知识库
   - **使用场景**：家庭 NAS、团队共享库
     - 用户 A 在 iOS 上生成知识库 → 导出 JSON
     - 用户 B/C 在 Android/Web 上导入同一份 JSON
     - 不需要重复调用 API，节省成本

5. **生成状态追踪**
   - 实时显示：已缓存条数 / 总条数
   - 最后更新时间：`最后更新：2026-07-30 14:23`
   - 生成速度：平均 2-3 条/秒（取决于 AI API 响应速度）

#### 数据流与集成

```
听歌历史 → RecommendationService
         → 提取流派、跳过模式、时间特征
         → 传递给 AI Playlist Service
            ↓
         AiPlaylistService
         ├─ 获取知识库 (SongKnowledgeCache)
         ├─ 补充新歌知识库（如需）
         └─ 调用 AI API → 生成歌单
            ↓
         新歌单保存到本地库
```

**使用场景：**
- 🎵 **个人用户**：一键生成主题歌单（治愈、高能、运动等）
- 👨‍👩‍👧‍👦 **家庭共享**：一个人生成知识库，全家人导入使用
- 💰 **降低成本**：多人协作时，共享知识库避免重复调用 AI
- 🔒 **隐私友好**：支持私有大模型，不上传数据到第三方
