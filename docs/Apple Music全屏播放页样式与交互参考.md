## 1. 总体设计语言

Apple Music 的播放页没有把功能拆成独立页面，而是围绕同一个“正在播放”舞台做模式切换：

1. 所有模式共享封面取色后的全屏模糊背景和当前播放上下文；默认封面态使用大封面信息结构，歌词/队列使用紧凑顶部歌曲信息
2. 中央区域根据用户意图在封面、歌词、待播列表之间切换；歌词沉浸态与电台态按实际能力收敛控制
3. 切换后不丢失播放上下文：歌曲、收藏、更多、进度、播放控制持续可见
4. UI 用低对比半透明控件退居背景，让当前内容（歌词或队列）成为唯一视觉焦点

### 1.1 背景

- 整屏以专辑封面的主色构成柔和的模糊色场；示例歌曲的橙棕/金色封面被扩展为大面积暖色背景
- 背景不是单色或线性渐变：顶部更亮、底部更深，局部保留模糊色块，形成封面被放大后的质感
- 所有文字和图标统一偏暖白色，而不是纯冷白，保证与封面色调融合
- 切歌或切换封面时，背景应交叉淡入至新封面色，不应突变

### 1.2 通用顶部信息区

歌词和队列等紧凑内容态使用相同的顶部骨架：

```
状态栏
歌曲信息行：方形小封面 | 歌名（粗）/ 艺术家（常规） | 收藏 | 更多
内容模式区：歌词 / 播放列表 / 播放控制
```

- 左侧封面约 72-80 dp，圆角很小（约 6-8 dp），不使用明显投影
- 歌曲信息在封面右侧左对齐：歌名约 24-28 sp、半粗；艺术家约 20-24 sp、常规字重、较低不透明度
- 收藏和更多位于右侧，均是约 48 dp 的圆形半透明点击面，而非裸图标
- 收藏为描边星标，更多为纵向三点；控件底色是暖白低透明度圆形，图标为高亮暖白
- 顶部信息区固定，切歌词/队列时不重新布局、不向上消失

### 1.3 底部播放控制区

歌词预览、队列与默认封面等普通歌曲可操作态使用稳定的底部播放控制区；歌词沉浸态隐藏该区域，电台态按直播能力使用专用控制：

- 细进度条横跨内容区左右边距，已播放部分使用暖白高不透明度，未播放部分使用更低不透明度
- 时间文本位于进度条下：左为已播时长，右为负的剩余时长，字号小、透明度低
- 上一首、播放/暂停、下一首水平居中，主播放键视觉最大；按钮本身不加圆形底板
- 最下方为三个模式/工具入口：歌词、AirPlay/投放、待播列表。选中项使用暖白实心圆角方形底板，未选中项只有线性图标
- 播放控制与中央内容之间留出稳定间距，长列表通过遮罩或裁切在控制区上方结束，不侵占底部控件

## 2. 截图 1：歌词沉浸态

### 2.1 画面结构

截图 1 是全屏播放页进入歌词后的沉浸态：

- 顶部歌曲信息区仍在；底部进度条与播放控制区被隐藏
- 歌词区从信息区下方开始，占据屏幕绝大部分高度，底部保留自然的淡出空间
- 顶部左侧出现三个小圆点，作为分页/歌词状态指示器；前两个高亮、第三个弱化
- 当前与临近歌词均左对齐，不居中

### 2.2 歌词文字层级

截图中的歌词并不是 AMLL 风格的“远处越来越模糊”，而是 Apple Music 的纯透明度层级：

- 前两组歌词可读性最高，使用大字号、粗字重、暖白色；示例中每一组可自动换为两行
- 已经过渡到较远位置的歌词保留同样的基本字号，但透明度明显降低
- 距离当前阅读区域更远的歌词近乎消失，只留下非常弱的文字轮廓
- 全部文字无高斯模糊、无外发光、无描边，也没有缩放造成的强烈大小阶梯
- 相邻歌词组之间的垂直留白显著大于同组自动换行的行距，读者可一眼识别“这一句/下一句”的结构

### 2.3 已确认交互规则

2026-08-06 用户确认：

1. 从封面默认态点击底部歌词按钮，先进入 `lyricsControls`（歌词预览态），保留进度条、时间、上一首/播放/下一首和底部三个入口
2. 预览态连续 **4 秒** 无操作后，自动切到 `lyricsImmersive`（歌词沉浸态），隐藏底部播放控制
3. 在预览态，歌词行保持现有点击 seek 能力；点击歌词行会跳转到该句时间点，并重置 4 秒倒计时
4. 在沉浸态，歌词行和歌词区不响应 seek，防止用户因浏览歌词而误跳播放位置
5. 在沉浸态轻触任意位置，恢复到歌词预览态，并重新开始 4 秒倒计时
6. 恢复预览后，点击底部歌词按钮关闭歌词并回到封面默认态
7. 任意触摸空白处、点击歌词 seek、拖动进度、播放/暂停、切歌都会重置倒计时；离开任意歌词模式时立即取消计时器
8. 无时间轴的纯文本歌词仍可进入歌词模式展示；完全没有歌词文本时，显示简洁空状态

## 3. 默认封面态（补充截图）

补充截图展示 Apple Music 全屏播放页的默认状态，即未选歌词、未选待播列表时的“封面常规态”。

### 4.1 画面结构

```text
状态栏
专辑名（建议 Luobo 补充，弱层级且可点击）
大尺寸方形专辑封面
歌曲名 / 艺术家                         收藏 / 更多
进度条 + 已播/剩余时长
上一首 / 播放或暂停 / 下一首
歌词 / AirPlay 或投放 / 待播列表
```

- 封面是此状态唯一的主视觉，约占屏幕宽度 58%-62%，居中放置，方形且不带明显圆角或阴影
- 背景仍由封面取色生成：示例中封面偏白绿，整页为低饱和浅绿到灰绿的模糊色场；它比歌词态/队列态更明亮，因为大封面承担了视觉焦点
- 歌曲名位于封面下方靠左，约 28-32 sp、半粗暖白；艺术家位于下一行，约 22-24 sp、常规字重且透明度略低
- 收藏与更多按键和歌曲信息行对齐，位于右侧；两者仍是半透明圆形点击面
- 封面下的歌曲信息、进度和播放控制构成紧凑操作区，底部三入口未选中时均是裸线性图标

### 3.2 关于“专辑名放在封面上方”的设计决策

**建议加入，且只作为弱层级的来源信息。**

理由：

1. 补充截图中状态栏与封面之间有可用留白，专辑名放这里可补足歌曲所属上下文，不会与封面、歌曲名或底部控制争夺空间
2. Luobo 已经能从 `Song` 获取专辑信息，用户点击专辑名还能直达专辑详情，形成比当前仅显示“正在播放”更明确的导航入口
3. 默认封面态适合展示专辑归属；切到歌词/待播列表后顶部空间改为歌曲信息和模式内容，专辑名不必强行保留

具体规范：

- 位置：封面上方，水平居中，距离封面约 16-20 dp；不放进封面内部，不使用胶囊背景
- 样式：约 16-17 sp、`FontWeight.w500`、暖白 70%-78% 不透明度；单行，超长省略
- 交互：整行是最小 44 dp 高的点击区，点击进入该歌曲的 `AlbumScreen`
- 内容：只显示专辑名；不加“来自”“专辑：”等前缀，不重复艺术家名
- 缺失降级：`album` 为空、未知或与歌曲名相同则不渲染；封面向上回收对应间距，保持视觉居中
- 触感：按下仅作轻微 alpha/scale 反馈；不要增加下划线、箭头或额外图标

不建议把专辑名做成大标题、封面标签或第二个副标题。歌曲名和艺术家已经在封面下方形成明确的信息层级，专辑名的职责是“可导航的归属”，视觉权重应低于它们。

### 3.3 可推导交互

2026-08-06 用户确认：

1. 默认封面态完整采用参考图布局：封面约 60% 屏宽，歌名/艺术家在封面下方，收藏/更多与歌曲信息同一行
2. 专辑名按 §3.2 弱层级置于封面上方，单行可点击进入 `AlbumScreen`
3. 点击大封面不执行任何操作；歌词仅由底部歌词按钮进入，避免存在隐藏快捷手势
4. 歌曲没有可跳转的专辑信息时，不显示专辑名且回收间距，让封面保持视觉居中；切歌时以内容淡入淡出/轻微位移吸收布局变化
5. 点击歌词/待播列表：中央内容分别切为歌词预览态/队列态，底部入口出现选中底板
6. 收藏：高频即时切换，不打开菜单；更多：打开截图 5 的底部 Action Sheet

## 4. 截图 2：带控制区的歌词预览态

### 3.1 画面结构

截图 2 与截图 1 的顶部歌曲信息、背景、歌词样式一致，但底部控制区仍可见：

- 歌词只占据中间可用高度，并在底部进度条前渐隐
- 进度条、时间、上一首/播放/下一首、底部三入口完整保留

### 4.2 交互意义

这是“歌词已选中，但用户仍在操作播放”的可交互态。它比截图 1 更适合作为 Luobo 的默认歌词模式，因为：

- 用户刚进入歌词时仍能调进度、切歌、暂停
- 仍能一眼看见歌词已被选中
- 控件不会遮住歌词：歌词区域通过渐隐处理自然让出控制区

### 4.3 与沉浸态的关系

歌词预览态是歌词按钮点击后的初始状态；详细的自动沉浸、恢复、seek 和无歌词降级规则已在 §2.3 确认。

## 5. 截图 3：待播列表初始态

### 5.1 画面结构

点击底部最右的待播列表按钮后，中央内容切换为队列：

- 顶部歌曲信息区不变
- 顶部信息区下方增加三枚横向排列的圆角胶囊按钮：随机、循环/重复、无限播放（Autoplay）
- 胶囊按钮为低对比暖白半透明底，图标低对比；它们代表队列播放策略，不抢内容焦点
- 控制按钮下方显示“继续播放”标题和“来自 [电台/播放来源]”副标题
- 队列项采用紧凑两行列表：左方形封面、中间歌名与艺术家、右侧三横线拖拽把手
- 列表首屏仅展示约 5 项，并在底部进度条前自然收口
- 选中的底部待播列表按钮有暖白实心圆角方形底板

### 5.2 队列项细节

- 封面约 64-72 dp，圆角约 8 dp
- 标题字号约 24 sp，艺术家约 18-20 sp 且透明度降低
- 行间距宽松，但行内元素对齐紧凑
- 拖拽把手不使用“删除”或“三点更多”，只表达可重新排序
- 当前播放项在截图中没有明显红色/等化器标记；当前上下文通过顶部歌曲信息和全局播放状态维持，不用在每一行额外制造噪声

### 5.3 已确认交互

2026-08-06 用户确认：

1. 点击队列行直接切换播放；保留现有单曲移除和右侧拖拽把手排序能力
2. 当前播放项仅用较亮/半粗标题作低调标识，不使用红色、等化器或动态播放图标
3. 三枚队列策略按钮分别控制随机、循环和自动续播；选中态通过填充色/图标不透明度体现
4. 队列内容可向上滚动，但播放控制区固定
5. 队列只剩当前曲、没有任何后续歌曲时，自动退出队列态并回到 `previousMode`

### 5.4 已确认：自动续播

自动续播采用“明确开启、队尾补歌、绝不改写用户队列”的规则：

1. 默认关闭；用户在队列页主动开启后持久化该选择
2. 只在剩余待播歌曲不超过 2 首时触发；每次在队尾追加 5 首
3. 用户手动添加的歌曲始终在自动续播歌曲之前；自动续播只补队尾，不重排、不插队
4. 候选优先级：服务端 `getSimilarSongs(currentSong)` → 本地知识标签相似 → 同艺术家/同风格 → 现有个性化推荐 → 本地库随机歌曲
5. 过滤当前曲、现有队列与最近播放歌曲；本次不新增“用户手动移除歌曲永久排除”机制，避免将播放页改版扩大为推荐系统重构
6. 复用现有 `AutoDjService + PlayerProvider` 的同步队列/音频源追加管线；不要在 UI 层直接修改 `_queue`

### 5.5 已确认：队列编辑边界

1. 正在播放的当前曲锁定：不可移除、不可拖拽重排；只允许编辑当前曲之后的后续歌曲
2. 上一首/下一首在队列边界不可用时置灰且不可点击，始终保留控件位置；不隐藏、不弹提示

## 6. 截图 4：待播列表滚动态

截图 4 展示播放列表向上滚动后的状态，重点不是新增组件，而是滚动边界：

- 顶部歌曲信息与三枚队列策略胶囊保持固定，不随列表滚动
- “继续播放 / 来源”标题同样作为队列区固定头部保留
- 只有歌曲列表内容向上滚动
- 列表到进度条附近被柔和裁切/渐隐，底部播放控制从不被列表覆盖
- 上方首项进入裁切区时不出现明显硬切，列表像被一个固定视窗承载

这意味着实现上不应使用“整个播放页一个 `SingleChildScrollView`”。应拆成固定的 Header、固定的队列控制/标题、`Expanded` 的可滚动队列视窗、固定的底部控制区。

## 8. 对 Luobo 现状的映射与差异

当前 Luobo 移动端全屏播放页在 `lib/screens/now_playing_screen.dart`，已有以下能力：

## 20. 实施前架构审查结论

### 20.1 新旧页面隔离

1. 新 Apple 风格页新建为独立 `AppleNowPlayingScreen` 及独立组件目录，旧 `NowPlayingScreen` 不增加模式分支、不承接新页面局部状态
2. 移动端入口只替换 `main_screen.dart` 中 `_openNowPlaying()` 的页面构造；保留原有 400ms 路由转场、诊断 route observer 和 iOS 音频会话恢复
3. 新页继续以 `PlayerProvider` 为播放业务状态唯一来源，不复制队列、播放进度、远端播放或睡眠定时业务逻辑

### 20.2 必须重写与可无行为抽取的边界

| 能力 | 新页面策略 | 原因 |
|---|---|---|
| 动态背景、封面、进度条、播放控制、页面内队列 | 新建 | 旧实现是私有 Widget 且与旧视觉/手势/主题高耦合 |
| 歌曲列表更多菜单、评分弹窗 | 无行为变化地抽出公共 action/presenter，旧 `SongTile` 与新页共同调用 | 维持用户要求的菜单项、条件与事件完全一致 |
| 变速、睡眠定时 | 复用 `PlayerProvider` API；展示层抽为可从新更多菜单调用的 action widget | 定时器和播放参数是跨页面业务状态，不能由新页重新持有 |
| 封面缓存/本地与网络路径判断 | 复用现有公共缓存与封面解析策略 | 避免破坏已实施的封面缓存优化 |

### 20.3 异步与状态红线

1. 新歌词和背景取色必须有独立请求代次/歌曲身份校验；旧响应不得覆盖新歌曲 UI
2. 新进度条必须实现 optimistic seek：用户拖动后维持目标显示，直到播放器确认位置到达目标附近，不能直接跟随慢速 position stream 回弹
3. 只允许新队列动作层调用编辑 API，确保当前曲锁定规则在 UI 入口层统一执行
4. 新页不复制旧自动车载 Timer；Wakelock 仅由新页当前歌词态申请，并在从车载页返回时重新计算

### 20.4 测试最低覆盖

- 纯单测：歌词 `songId + generation` 会话、4 秒计时器暂停/恢复、主模式转移、队列当前曲锁、自动续播候选与队尾追加
- Widget 测试：封面/歌词/队列/电台/空状态布局、系统返回优先级、更多菜单暂停计时、字体放大与小屏布局、按钮语义/点击区
- 真机验证：快速连续切歌、后台恢复、车载往返、远端/系统媒体控制切歌、浅色封面可读性、无封面与封面加载失败
