# Luobo 图片缓存与播放性能优化技术文档

> 状态：方案设计（待实施）
> 范围：封面图片缓存策略、播放页/列表卡顿优化、设置页缓存管理增强

## 1. 背景与目标

当前痛点：

- 歌曲列表封面加载慢；播放页封面慢；多处"重新加载"；
- 频繁切歌、打开播放页、车载页时 UI 卡顿明显；
- 设置页无法查看缓存占用量，清空缓存无二次确认。

目标：

- 同一封面跨页面/跨歌曲命中同一缓存，减少重复下载与 Navidrome 转码；
- 消除播放页大图解码与背景模糊带来的切歌卡顿；
- 设置页可查看各缓存占用量并安全清理。

## 2. 现状盘点（全 App 缓存清单）

| 缓存 | 存储 | 写入时机 | 过期/驱逐 | 清空时机 |
|------|------|---------|-----------|---------|
| 封面磁盘缓存 `coverCacheManager`（`utils/image_cache.dart`） | 磁盘 | 封面首次请求 | `stalePeriod 60 天`；`maxNrOfCacheObjects 1000`（LRU） | 设置页手动 / 关图片缓存开关 / 退出登录（`auth_provider.dart:356`） |
| 图片内存缓存（Flutter `ImageCache`） | 内存 | 图片解码后 | 300 张 / 150MB | 内存压力自动；退出登录未显式清理 |
| SQLite 本地曲库（歌曲/专辑） | 磁盘 DB | 全量同步 | 距上次同步 >6 小时自动后台刷新（`library_provider.dart:379-380`） | 每次同步前 `clearServerData()` 重建；退出登录强制全量重同步 |
| SharedPreferences（歌单/艺术家 JSON） | 磁盘 | 拉取成功后 | — | 退出登录 `prefs.clear()` |
| BPM 分析缓存 | 磁盘 | 分析成功后 | — | 设置页手动 / 退出登录 |
| AI DJ 缓存 | 磁盘 | 推荐生成后 | — | 手动清 |
| 歌词（`lyrics_manager`） | 内存 | 加载后 | 随播放器重置 | — |
| 离线下载 | 磁盘 | 用户主动下载 | — | 手动删除（非缓存，独立管理） |

已有基础设施（确认在库）：统一 CacheManager `coverCacheManager` 已全 App 传参、`ImageCacheConfig` 300/150MB、`ImagePreloader` 预热、设置页"存储"tab（开关 + 清空按钮 + BPM 缓存数量 + 离线下载大小）。

## 3. 问题根因分析

### 3.1 加载慢（缓存相关）

1. **URL 高度碎片化**：同一封面按 size 生成不同 URL，全 App 使用数十种尺寸（列表 120、AlbumArtwork 按 `(尺寸×DPR).clamp(200,800)`、播放页 **1200**、车载/首页/迷你条 600、锁屏 size 0 原始分辨率）。每种 size = 独立下载 + 独立磁盘条目 + Navidrome 独立转码。
2. **歌曲封面未归一**：`player_provider.dart:1564` 用 `song.coverArt ?? song.id` 兜底——同一专辑的歌曲 coverArt 为空时生成 N 个不同 URL，专辑封面被重复下载 N 次。
3. **磁盘上限被尺寸稀释**：`maxNrOfCacheObjects 1000` 平摊到多种尺寸后，每种尺寸实际容量仅数百张，大库仍会驱逐重下。

### 3.2 UI 卡顿（缓存无法解决）

| 来源 | 说明 |
|------|------|
| 播放页 1200px 主图解码 | `now_playing_screen.dart:502-521` 每次切歌请求 1200px；即使磁盘命中，主 isolate 解码 1200×1200 位图（5.76MB、数十 ms）仍卡；且该处未设 `memCacheWidth` |
| 背景模糊 `_DynamicBackground` | 每切歌对（大概率 1200px）封面做高斯模糊 |
| 每行 TextPainter 测量 | SongTile 副标题自适应（`song_tile.dart`）与迷你条歌名自适应（`mini_player.dart`）每次 build 做一次文本测宽 |
| Artist tab 重复计算 | `artistSongCounts` 每次 Consumer rebuild 全量遍历 `cachedAllSongs`（`library_screen.dart`） |
| 迷你条毛玻璃 | `BackdropFilter(blur 28)` 常驻每帧渲染（`mini_player.dart:87-88`） |

## 4. 优化方案设计

### 4.1 封面键归一（核心）

```
effectiveCover(song) =
    song.coverArt                        // 服务器返回（Navidrome 通常为专辑封面 id）
    ?? 该专辑的 coverArt（按 albumId 查 cachedAllAlbums）
    ?? song.id（最后兜底，仅确实无封面）
```

- `LibraryProvider` 新增 `effectiveCoverArt(Song)`；
- 所有 UI（SongTile 列表、播放页 `_loadArtwork`、player_provider cast/锁屏 URL、车载页）统一使用。

### 4.2 尺寸档位统一

固定 3 档：**120（列表/缩略图）· 300（通用封面/播放页主图/背景模糊）· 600（仅 AndroidAuto/锁屏）**

- 播放页主图 1200 → 300（与通用档合并，命中率翻倍、解码减半）；
- `AlbumArtwork` 尺寸计算对齐档位（不再 DPR 连续变化）；
- 移除 `getCoverArtUrl(song.coverArt ?? song.id)` 的 song.id 兜底（改走 4.1）。

### 4.3 解码与渐进展示

- 所有 `CachedNetworkImage` 统一 `memCacheWidth`（按档位 × DPR，上限 800）；
- 播放页：先渲染 200px 缩略图（列表大概率已缓存），600/300px 大图后台加载完替换；
- 背景模糊用缩略图（120/300）而非大图，解码成本降 10-36 倍。

### 4.4 空间换时间

- 全量同步完成后后台**分批预热 120 档全部专辑封面**（限速 6 并发 + 批间 sleep，避免 Navidrome 转码风暴；增量：只预热新增）；
- 播放页/车载常用封面按需预热当前专辑 300 档。

### 4.5 质量换时间

- 播放页 600 → 300（见 4.2），下载/解码减半，肉眼无差别；
- 服务端可另配 Navidrome 封面转码缓存预热脚本（一次性 curl 全库 120px），首访命中服务端缓存。

### 4.6 计算优化（治滚动卡顿）

- SongTile 副标题/迷你条歌名：TextPainter 测量结果缓存（同文本+同宽度不重测）；
- `artistSongCounts` 移到 Provider 层，按 `_cachedAllSongs` 变更增量维护；
- mini_player 毛玻璃：降 sigma 或改为非 glass 模式降耗。

### 4.7 设置页"存储"tab 增强

1. **占用量显示**：
   - 图片磁盘缓存：`coverCacheManager.getCacheSize()`；
   - 图片内存缓存：`PaintingBinding.instance.imageCache.currentSizeBytes`；
   - BPM 缓存大小（或沿用数量）；
   - 进入页面异步统计（放后台 isolate），清空后刷新归零。
2. **二级确认**：清空全部缓存 / BPM 单项清空 加 AlertDialog（复用现有删除下载确认样式）；
3. 退出登录补清：内存图片缓存（`imageCache.clear()`）+ Auto DJ 缓存。

## 6. 验证与监控

- Profile 模式（非 Debug）测：连续切歌帧率 ≥ 55fps；打开播放页/车载页无掉帧；
- DevTools 看 `ImageCache` 命中率（`PaintingBinding.instance.imageCache` 统计）与内存峰值；
- 检查 `coverCacheManager` 缓存目录大小与命中（服务端日志看 getCoverArt 请求量是否大幅下降）；
- 同专辑切歌 / 列表进播放页应**零新增 getCoverArt 请求**（命中磁盘 + 同尺寸）。

## 7. 明确不做（本期范围外）

- 不重构播放器/音频流架构；
- 不实现封面 CDN；
- 不改 Navidrome 服务端配置（仅提供可选预热脚本思路）；
- 不做全库离线下载。
