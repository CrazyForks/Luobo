## 1. 背景与目标

道理鱼库内有 **7 部有声书**（admin stats `"audiobooks":7`），自研 `/api` 层提供 `GET /api/library/audiobooks`（列表）端点，但：

- 章节获取 / 播放 URL / 服务端进度均**未在文档中记录**（见 §3 前置验证）
- Subsonic 层 `getBookmarks` 读写**不支持**（`Unknown endpoint`）→ 服务端无法记进度

目标（用户需求原文归纳）：

1. 登录道理鱼后，**有声书入口放在"电台"的位置**（音乐库快捷区那颗 电台 tile）
2. 进入后是**有声书列表页**
3. 点某一本 → **分页形式的章节列表页**
4. 点章节 → 播放
5. 有声书**无歌词** → 播放时**不自动进入车载模式**
6. **核心**：无论切歌还是切到其他有声书，**再回来必须记住之前那本的播放章节与进度**

## 3. 有声书 API 形状（✅ 已实测，2026-08-10 接口文档 v3.1 更新）

道理鱼有声书业务在 `/Music2` 源（7 部：相声/曲艺/郭德纲讲历史/今古奇观/三体×2/鬼吹灯），**不在 Subsonic 音乐索引里**（search3 搜不到），入口走自研 `/api/library/audiobooks*`。

| 端点 | 形状 | 关键点 |
|---|---|---|
| `GET /api/library/audiobooks?limit=&sort=` | `{"items":[{...}],"search":"","skip":0,"take":100,"total":N}` | 顶层分页 skip/take/total；`?limit=` `?sort=` 有效 |
| `GET /api/library/audiobooks/{abk_id}` | 列表项字段 + **内嵌 `episodes[]` 全量章节** | 详情页可一次拿全 |
| `GET /api/library/audiobooks/{abk_id}/episodes?limit=&skip=` | `{"audiobookId":...,"chapters":[{...}],"count":N,"episodeItems":[...]}` | **服务端分页可用**；chapters/episodeItems 内容重复，取 chapters；⚠️ 必须带 `library/` 前缀（无前缀 → NOT_FOUND）；⚠️ **`count` 是当页返回条数（实测取 2 章 → count:2），不是总章节数——分页 totalPages 必须用列表项 `episodeCount` 计算**（2026-08-11 真机发现，原设计误当 count 为总数导致 100+ 章只有 1 页） |
| **播放复用 ⭐** | `GET /rest/stream?id=<abe_...>&format=raw` → 200 audio/mp4（m4a 直出） | **章节 id（`abe_`）可直接走 Subsonic 层播放**，明文认证，无需客户端传 token → 无缝复用现有 stream 逻辑 |
| 收藏 | `GET/POST/DELETE /api/favorites/audiobooks`（id 前缀 `fab_`） | 一期可不做收藏 |
| 服务端进度 | 文档未记录进度/bookmark 端点 | → 进度记忆**纯客户端**（§9）确认 |

**列表项字段**：`id(abk_)` `title` `baseTitle` `slug` `status(PUBLISHED)` `isSerializing` `narrators[]` `narratorDisplayName`(可 null) `categories[]` `tags[]` `episodeCount` `totalDurationSeconds` `lastEpisodePublishedAt` `updatedAt` `playCount` `favoriteCount` `sourcePath(/Music2/...)`

**章节对象字段**：`id(abe_)` `title` `order`（章节序，1-based）`durationSeconds` `audioPath` `audioUrl`(自研带 token 流地址，**不用**，走 Subsonic) `publishedAt` `isPreview`

> 注意：列表/章节响应**均无封面字段** → 有声书封面**占位图兜底**（已确认决策）。

## 4. 总体设计

```
音乐库快捷区「电台」tile ──(serverFamily=='daoliyu')──▶ 换成「有声书」tile
                                                        │
                                                        ▼
                                              AudiobookListScreen（有声书列表页）
                                                        │ 点某本
                                                        ▼
                                            AudiobookDetailScreen（章节列表页，分页）
                                                        │ 点章节 / 继续收听
                                                        ▼
                                   playAudiobookChapter() → 复用 PlayerProvider 播放栈
                                                        │
                    ┌───────────────────────────────────┼──────────────────────────┐
                    ▼                                   ▼                          ▼
            无歌词（短路歌词加载）            不自动进车载模式（守卫加参）   每本书进度/章节本地持久化（核心）
```

设计原则：

- **播放全栈复用**：章节映射为 `Song` 对象（title=章节名，album/artist=有声书名），走现有 `playSong` 队列播放 → 迷你播放器、全屏播放页、锁屏、上一曲/下一曲全部自然生效，零新播放代码。
- **独立于歌曲队列**：有声书播放时**不写** `persistent_queue_*`（避免重启后当普通歌曲恢复、且车载守卫状态丢失），进度走独立的 `audiobook_progress_*` 存储。
- **道理鱼专属**：入口、数据层全部 `isDaoliyu` 分支，非道理鱼服务器零影响（电台照旧）。

## 5. 数据层（`lib/services/subsonic_service.dart`）

```dart
/// 有声书列表。GET /api/library/audiobooks?limit=100
/// → {"items":[...], "skip":0, "take":100, "total":N}
Future<List<Audiobook>> getAudiobooks() async {
  if (!isDaoliyu) return [];
  final data = await _apiGet('/api/library/audiobooks?limit=100');
  final items = data?['items'] as List<dynamic>? ?? [];
  return items.map((e) => Audiobook.fromJson(e as Map<String, dynamic>)).toList();
}

/// 章节列表（服务端分页）。GET /api/library/audiobooks/{id}/episodes?limit=&skip=
/// → {"chapters":[...], "count":N}（episodeItems 与 chapters 重复，取 chapters）
Future<AudiobookChapterPage> getAudiobookChapters(
  String audiobookId, {
  int skip = 0,
  int take = 50,
}) async {
  final data = await _apiGet(
    '/api/library/audiobooks/$audiobookId/episodes?limit=$take&skip=$skip');
  final chapters = data?['chapters'] as List<dynamic>? ?? [];
  return AudiobookChapterPage(
    chapters: chapters.map((e) => AudiobookChapter.fromJson(e as Map<String, dynamic>)).toList(),
    total: data?['count'] as int? ?? 0,
  );
}
```

- 依赖 `_apiGet()`（JWT + 401 重登重试），自动跟随 `activeBaseUrl`（LAN↔远程）。
- 章节→Song 映射 `_audiobookChapterToSong()`：`id=章节 id(abe_)`（**直接喂 Subsonic `/rest/stream`**，明文认证）、`title=章节 title`、`album=artist=有声书 title`、`duration=durationSeconds`、`track=order`；**`albumId/artistId` 置 null**（避免播放页点专辑/艺人名跳转不存在的专辑页）；`coverArt` 置空 → 占位图。
- 全部失败返回空列表 + 上层错误态（与现有列表页一致）。
- **收藏**（`/api/favorites/audiobooks`）一期不做，仅留扩展点。

### 7.4 长章节/合集快速导航（类型感知，2026-08-21）

**背景**：连续滚动后几百条内容（如郭德纲相声合集几百段）浏览成本高；且两类内容用户心智不同——**编号型**（叙事书：三体/鬼吹灯/今古奇观）章节有序，用户按编号找章（"我在第 240 章"）；**合集型**（相声/曲艺）每段是独立作品、**标题才是身份**（"我要幸福"），编号无意义。

**端上类型判断**（纯客户端，服务端零改动）：
1. 优先读服务端列表项**已有字段** `categories[]`/`tags[]`（模型补齐解析；含「相声/曲艺/评书」等合集类标记 → 合集型）。
2. 兜底**标题模式启发式**：章节标题「`第X章/回/节/集/部/卷/话/篇`、`Chapter N`、`卷一`、**`001 数字编号前缀`**」占比 ≥ 60% → 编号型，否则合集型（O(n) 一次扫描，全量列表已在内存；⚠️ 2026-08-21 真机修正：三体标题实测为「001/002」数字编号格式，原正则只认「第X章」导致误判合集型）。
3. 判定时机：`_loadChapters` 成功后计算（新鲜拉取与缓存命中两路都算）。

**按类型的工具分配**（详情页 AppBar 工具按钮按类型渲染）：

| 工具 | 编号型 | 合集型 | 实现 |
|---|---|---|---|
| 章节直跳（输入章号） | ✅ | — | 输入 1..N → `index×72` 精确 jumpTo + 高亮（复用 itemExtent） |
| 书内搜索（标题过滤） | — | ✅ | 全量列表在内存，纯前端子串过滤，零服务端接口 |
| 快滑索引条（拖拽+章节气泡） | ✅ | ✅ | 右侧可拖拽条，拖动气泡显示「第 X 章 · 标题」，松手精确落位；<30 章自动隐藏（2026-08-21 真机调低） |

- 编号型**不显示**搜索框（编号标题找章靠编号，搜索冗余）；合集型**不显示**章节直跳（编号无意义）。
- 若后续发现编号书也有按名找章需求，搜索入口同一管线可复用，成本低。

### 8.2 新入口 `playAudiobookChapter(Audiobook book, List<AudiobookChapter> chapters, int index)`

> **⚠️ 交互自查修正（2026-08-10）**：`_isPlayingAudiobook` 置位必须由 `playSong` 统一处理（见下），否则 `_saveQueueState`/歌词短路/scrobble 判断错乱；必须 `forcePlay: true` 否则 `playSong` 的 same-song toggle 会吞掉 seek 语义；恢复续播**复用现有 `_prepareCurrentSong` 恢复路径**（`resumePositionMs` 参数），而非 playSong 后立即 seek。

1. 先保存**上一本**有声书进度（若在播有声书，见 §9.3）。
2. **队列 = 全书章节列表**（不是当前显示页）：播放时拉一次全量章节（**统一走 `GET /api/library/audiobooks/{abk_id}/episodes?limit=10000&skip=0`**，与分页共用解析函数，避免与 detail 端点 `episodes[]` 字段漂移）→ 章节→Song 列表。
   - ⚠️ **P4 失败处理**：全量拉取失败（网络）→ snackbar「章节加载失败，请重试」，**不清当前播放状态**。
   - 同一本书内切章：复用现有队列（`playSong` 已有"队列含该 song → indexWhere"分支），不重复拉取/重建。
3. **强制顺序播放 ⚠️（Bug B6）**：进入有声书时保存当前 `_shuffleEnabled` 并**置 false**，退出有声书（切歌/电台/停止）时恢复；`skipNext/skipPrev` 在有声书下始终按队列顺序，不参与 shuffle。
3. 调 `playSong(first, playlist: 全量, startIndex: index, forcePlay: true, audiobook: true, audiobookBook: book, resumePositionMs: 保存进度或 null)`。
   - **`playSong` 内部新增 `audiobook`/`audiobookBook`/`resumePositionMs` 可选参数**：
     ```dart
     Future<void> playSong(Song song, {List<Song>? playlist, int? startIndex,
         bool forcePlay = false, bool audiobook = false, Audiobook? audiobookBook,
         int? resumePositionMs}) async {
       // 从有声书切到普通歌/其他书：先保存旧书进度
       if (_isPlayingAudiobook && !audiobook) _saveAudiobookProgress();
       ...
       // 队列设置后、_saveQueueState 之前（原 _currentSong 赋值处，顺序不可反）：
       _isPlayingAudiobook = audiobook;
       _currentAudiobook = audiobook ? audiobookBook : null;
       _audiobookChapterIndex = audiobook ? (章节 order) : null;  // order 从 Song.track 取
       _position = Duration(milliseconds: resumePositionMs ?? 0);  // 复用 _prepareCurrentSong 的 seek 恢复
     }
     ```
   - **⚠️ B11 连锁修正：所有内部调用 `playSong` 的队列内切换点必须透传 audiobook 状态**——`skipToIndex`（`player_provider.dart:2657`，非 gapless 走 `playSong(forcePlay:true)`）加 `audiobook: _isPlayingAudiobook, audiobookBook: _currentAudiobook`。否则非 gapless 切章会把 `_isPlayingAudiobook` 置 false（进度不保存、车载/统计/shuffle 全恢复）。
   - `_prepareCurrentSong`（`player_provider.dart:2997`）已有 `if (_position.inMilliseconds > 0) await _audioPlayer.seek(_position)` —— 音频 ready 后自动续播，与歌曲重启恢复同一路径。⚠️ **B14 已知限制**：cast/UPnP 播放中本地播放器已 stop，恢复 seek 不生效（投屏时"继续收听"从 0 播），一期接受。
4. 有保存进度且为用户点"继续收听" → 传 `resumePositionMs: savedPositionMs`（forcePlay 保证非 toggle）。

### 8.3 与普通歌曲互切（核心要求的保证）

| 事件 | 处理 |
|---|---|
| 有声书 → 普通歌曲（`playSong`） | `playSong` 开头（`!audiobook` 分支）保存有声书进度；置 `_isPlayingAudiobook=false` |
| 有声书 → 另一本有声书 | 保存上一本 → 播放新本（新本进度在进入详情页时已读取，恢复逻辑见 §9.4） |
| 有声书 → 电台（`playRadioStation`）⚠️ | **清 `_isPlayingAudiobook=false; _currentAudiobook=null`**（否则标志残留：车载守卫误排除电台、进度误写旧书）；`stopRadio` 同样 |
| 切后台 / 暂停 | 立即保存当前有声书进度 |
| 章节播完（`_onSongComplete`） | 若在播有声书：bookmark 推进到 `order+1`、position=0；**最后一章 → 停止播放 + 标 completed，不触发 AutoDJ/推荐续播（Bug B7）**；跳过 scrobble/`_recordSongEnd` |
| **gapless 切章（`_onCurrentIndexChanged`）⚠️** | 与 `_onSongComplete` 同等处理：跳过 scrobble/歌词加载，**bookmark 推进到新章 order、position=0**。两个钩子都必须加有声书分支（gapless 与非 gapless 各走其一） |
| **repeat 隔离（Bug B10）⚠️** | 有声书下强制 `_repeatMode=off`（`RepeatMode.one` = 单章死循环；`RepeatMode.all` = 末章循环回第一章，与 B7 冲突）；**shuffle/repeat 按钮全 UI 面隐藏/禁用**：播放页、迷你播放器（`mini_player.dart:375,410`）、桌面播放栏（`desktop_player_bar.dart:409,462`）；退出有声书恢复用户原 repeat/shuffle 设置 |
| **AutoDJ 三触达点（Bug B7/B16）⚠️** | `_handleEndOfQueue`（`player_provider.dart:1686`）、`skipNext`（2458）、`_onCurrentIndexChanged`（3048，gapless 切章）**三处**都检查 `_isPlayingAudiobook` → 有声书下不追加 AutoDJ 歌曲 |

### 8.5 播放统计全面隔离 ⚠️（Bug B9）

有声书播放**不得污染任何歌曲维度的听歌统计**。不止 scrobble，本地统计/推荐反馈同样会收到 `abe_` 章节 id（污染首页最近播放、推荐信号、听歌报告、历史/常听榜）。

- **统一 gate**：把 `playSong` / `_onCurrentIndexChanged` / `_onSongComplete` 里的全部"播放行为记录"收敛为一个私有方法 `_trackPlayback()`（内含 scrobble 起始/播完、`RecommendationService` 最近播放写入、推荐 `countPlay` 信号、本地 playCount 持久化），方法开头 `if (_isPlayingAudiobook) return;`。
- 覆盖清单：scrobble（服务端）、`_recentlyPlayed`（首页最近播放，recommendation_service:55）、推荐信号 `playCountSignal`/`countPlay`（recommendation_service:16）、听歌报告数据源（listening_report_screen 的 playCount/skipCount/completionRate）、历史/常听榜（history_screen:89、library_screen:415）。
- 道理鱼 scrobble 本身可用，但只对真实歌曲记录。

### 8.6 队列持久化隔离

`_saveQueueStateImmediate`（`player_provider.dart:247`，真正写库处）**开头**：`if (_isPlayingAudiobook) return;`

### 8.8 播放页歌曲操作隔离 ⚠️（Bug B8 + B12）

有声书播放时，全屏播放页/歌曲菜单对当前曲的**歌曲专属操作**（收藏 `star(id)`、加入歌单 `addToPlaylist(id)`，`now_playing_screen.dart:2713-2724, 2756+`）会把 `abe_` 章节 id 当歌曲打 Subsonic 端点 → 无效请求 + 脏数据。

- `_isPlayingAudiobook` 时**隐藏/禁用**（全播放 UI 面，UI 按钮层穷举补全）：
  - **收藏**：播放页（`now_playing_screen.dart:2713`）、迷你播放器（`mini_player.dart:358 toggleFavorite`）、桌面播放栏（`desktop_player_bar.dart:312`）、右侧栏当前歌卡（`right_sidebar.dart:44`）
  - **加入歌单/添加到队列/下一首播放**：播放页（`now_playing:2685` 加歌单）、歌曲菜单（B12）
  - **评分**（P5，star_rating_widget）、**相似歌曲**（P6）
  - **歌词按钮**（可选）：播放页（`:1598`）、桌面播放栏（`:351`）——有声书无歌词

### 8.9 队列内切换的状态透传（Bug B11）

非 gapless 模式下 `skipNext/skipPrevious/skipToIndex` 内部调用 `playSong(forcePlay: true)`（`player_provider.dart:2657-2662`）——**必须透传 audiobook 状态**：`audiobook: _isPlayingAudiobook, audiobookBook: _currentAudiobook`。否则队列内切章把 `_isPlayingAudiobook` 置 false → 进度不保存、车载/统计/shuffle 全恢复（见 §8.2 连锁修正）。

## 9. 进度记忆（核心，纯客户端）

### 9.1 存储（新文件 `lib/services/audiobook_progress_store.dart`）

SharedPreferences，key 带服务器维度（防换服务器串数据）：

```
audiobook_progress_v1_<serverKey>
serverKey = sha256(serverUrl + localUrl + username)[0:12]   // 仿 persistent_queue_server 思路

value = {
  "<audiobookId abk_>": {
    "chapterOrder": 3,          // 1-based 服务端章节序（order）
    "chapterId": "abe_xxx",     // 兜底定位
    "positionMs": 1245000,
    "completed": false,         // ⚠️ P1：听完最后一章标 true（保留条目，"已听完"由此显示）
    "updatedAt": "2026-08-10T12:00:00Z"   // 可做"最近收听"排序
  }
}
```

> ⚠️ **P1 语义澄清**：听完 = `completed: true` **保留条目**（章节行显示"已听完"，点行从头重听）；`remove()` 仅用于书被删除/用户主动清除。`recent()` 排除 completed。

接口：

```dart
class AudiobookProgressStore {
  AudiobookProgress? load(String serverKey, String audiobookId);
  void save(String serverKey, AudiobookProgress p);
  void remove(String serverKey, String audiobookId);   // 书被删除/用户清除
  List<AudiobookProgress> recent(String serverKey, {int limit}); // "继续收听"候选（排除 completed）
}
```

> ⚠️ **P2 实现注意**：store 内维护**内存 map 缓存**（per serverKey），`save()` 只改内存并序列化快照落盘——位置流 1s 写 / 切歌同步写 / 退后台写多路并发时避免读-改-写竞态丢更新。

### 9.2 写入时机（多路兜底，保证"切了也记得"）

1. **位置流**：`_position` 更新时（现有 1s 节流回调内）→ `_isPlayingAudiobook` 时写 `positionMs`（顺手也存 `chapterOrder/chapterId`）；**若 `positionMs > 本章时长×95%`（如用户拖进度条跨章）→ 顺手推进 `chapterOrder`，避免恢复时先定位旧章再被自愈逻辑推走**。
2. **切换**：`playSong`（切普通歌/其他有声书）开头**同步**保存一次。
3. **暂停/退后台**：`didChangeAppLifecycleState` pause/inactive 分支追加保存。
4. **章节播完**：`_onSongComplete` 推进 bookmark（§8.3）。

### 9.3 恢复时机（"再回来"）

- 进入 `AudiobookDetailScreen` 时 `load(serverKey, bookId)` → 有进度则在对应章节行显示"已播至 mm:ss" + 恢复图标；**页面定位到该章节所在页**（`initialPage = (savedOrder-1) ~/ 50`）。
- 点行尾"恢复图标"（或行上的"继续收听"按钮）→ 按 `chapterOrder`（或 chapterId 兜底）在全量章节列表中定位 index → `playAudiobookChapter(book, fullChapters, index)` 并 `seek(savedPositionMs)`。
- 点普通章节行 → 从 0 播（新进度覆盖旧进度即可）。
- （可选 P1）有声书列表页顶部"继续收听"banner：`recent(serverKey, limit:1)`，**排除 completed 的书**（已听完的不占 banner，或显示"已听完 · 点击重听"）。**点击行为 = 进入该书详情页并定位到进度章节**（用户再点播放），而非直接开播——避免误触打断当前播放，符合大厂惯例。

### 9.4 边界与自愈

| 场景 | 处理 |
|---|---|
| 进度超过章节时长 | `min(positionMs, durationMs)` 截断；超过 95% 视为该章完成 → 落到下一章 pos 0 |
| 章节被删/书目变化 | 按 `chapterOrder` 定位，越界则回退到第 1 章 pos 0；`chapterId` 不匹配时同样回退 |
| 换服务器 | `serverKey` 隔离，天然不串 |
| 本地清理 | 保留最近 N=20 本，超出按 `updatedAt` 淘汰 |
| 杀进程 | 位置流 1s 节流 + 暂停/退后台兜底，最坏丢 1s |

**已知限制（记录不阻塞）**：道理鱼 search3 搜不到有声书（文档实测"不在 Subsonic 音乐索引"）→ 全局搜索不命中有声书，一期接受；二期可接自研 `/api/tracks?search=` 或 audiobooks 搜索。

**性能风险（P7，实现时验证）**：gapless 模式 + 大书时 `_buildAndSetConcatenatingSource`（`player_provider:2938`）用 `Future.wait` **并发构建全部章节源** → 首播构建延迟/内存峰值。实测库最大 120 章无碍；实现时若大书卡顿，限制 gapless 仅用于歌曲或章节切换重建。

**定时关闭复用说明**（2026-08-10 确认，无需新增代码）：
- 现有 `PlayerProvider.setSleepTimer()`（`player_provider.dart:1175-1246`）已支持：档位 15/30/45/60/120 分钟 + 自定义、`endCurrentSong`（播完当前曲/章停）、30s 淡出、取消、倒计时显示；UI 入口在全屏播放页 AppBar（`now_playing_screen.dart:1645, 1816-2070`）。
- 与有声书的联动天然成立：到点 `_doSleepTimerStop()` = `pause()`（保留队列与位置，进度由位置流 1s 节流保存）；`endCurrentSong` 已同时挂在 `_onSongComplete`(1644) 与 `_onCurrentIndexChanged`(3026) → gapless/非 gapless 的"播完本章"均覆盖。
- ⚠️ 编码注意：`_onSongComplete` 内 sleepTimer `endCurrentSong` 检查(1644) 在函数开头、先于 B7 的"末章停止/标 completed"，两者都要求停、不冲突，保持该顺序即可。
