# Luobo 歌词页快速下滑关闭技术方案

> 状态：已实现（2026-08-07）
> 范围：移动端歌词页（`SyncedLyricsView` → `AMLLLyricsWidget`）新增"快速下滑关闭歌词"交互；**不改变既有上下滑滚动歌词的行为，不改变歌词渲染管线**
> 方案确认：2026-08-07 用户拍板 —— ① 仅列表滚到顶部后快速下拉才关闭；② 仅移动端启用；③ 检测到即直接关闭（无退场动画）
> 设计约束：与歌词滚动零冲突（不参与手势竞技场）；复用既有 `SyncedLyricsView.onClose` 关闭链路；内嵌精简歌词（`CompactLyricsView`）不受影响

---

## 1. 背景与目标

### 1.1 用户反馈

歌词页当前上滑/下滑是滚动歌词列表。希望在"快速下滑"时关闭歌词界面，且不能干扰正常的歌词滚动。

### 1.2 目标

- 快速下滑（甩动）关闭歌词页，回到播放页封面态
- 慢速下拉（读歌词）、列表中部快速下滑（滚回顶部）均不触发
- 不破坏逐行滚动、点击 seek、回到当前行等既有交互

---

## 2. 现状手势栈（代码实证）

| 层 | 组件 | 竖直手势 |
|---|---|---|
| 外层 | `_NowPlayingScreenState` 的 GestureDetector（下拉关闭播放页） | 歌词模式下已禁用（`_showLyrics ? null : handler`） |
| 中层 | `SyncedLyricsView`（歌词全屏页） | 无竖直拖拽；`onClose` 回调已存在 |
| 内层 | `AMLLLyricsWidget` 的 `ListView.builder` + `BouncingScrollPhysics` | **独占竖直拖拽**（即"上下滑移动歌词"） |

关键事实：

- 关闭链路已就绪：`SyncedLyricsView.onClose` → `_showLyrics = false`（`now_playing_screen.dart:955`），无需新开通道
- `AMLLLyricsWidget` 已有 `NotificationListener<ScrollNotification>`（`synced_lyrics_view.dart:1198`），`OverscrollNotification` 是其子类，天然流经同一监听器
- `BouncingScrollPhysics` 保证全平台（含 Android）在越界时产生 overscroll 通知

---

## 3. 方案对比

| 方案 | 思路 | 手势冲突 | 结论 |
|---|---|---|---|
| **A. 观察 OverscrollNotification + 速度阈值** | 列表在顶部 + 负越界 + 快速甩动 → 触发 `onClose` | **零冲突**（只观察不抢手势） | ⭐ 采用 |
| B. RawGestureDetector 自定义 recognizer | 在手势竞技场与 ListView 竞争 fling | 高，易破坏歌词滚动 | 弃 |
| C. 外层 GestureDetector onVerticalDragEnd | ListView 已赢得竞技场，外层收不到事件 | 不工作 | 弃 |
| D. Dismissible 包裹 | 与内层竖直滚动直接冲突 | 高 | 弃 |

方案 A 触发条件（三条件同时满足）：

1. 列表已滚到顶部（`metrics.pixels <= 0`）
2. 继续下拉越界（`overscroll < 0`）
3. 甩动速度超阈值（`velocity < -700 px/s`，负值 = 向下甩动）

---

## 4. 实现（全部在 `lib/widgets/synced_lyrics_view.dart`）

### 4.1 `AMLLLyricsWidget` 新增两个可选参数

```dart
/// 快速下滑关闭歌词页（列表顶部 + 下拉越界 + 甩动速度超阈值时触发）。
/// 可选：内嵌精简歌词（CompactLyricsView）不传则不启用。
final VoidCallback? onFlingDownClose;

/// 是否启用快速下滑关闭（仅移动端开启，桌面触控板快速甩动易误触）。
final bool enableFlingDownClose; // 默认 false
```

### 4.2 触发检测（既有 NotificationListener 内新增分支）

```dart
// 快速下滑关闭：列表已滚到顶部 + 下拉越界（overscroll<0）+ 甩动速度
// 超阈值。只观察滚动通知、不参与手势竞技场，与歌词滚动天然不冲突。
if (widget.enableFlingDownClose &&
    n is OverscrollNotification &&
    n.metrics.pixels <= 0 &&
    n.overscroll < 0 &&
    n.velocity < _kFlingCloseVelocity) {
  widget.onFlingDownClose?.call();
}
```

阈值常量（`_AMLLLyricsWidgetState` 内）：

```dart
/// 快速下滑关闭的速度阈值（px/s，负值=向下甩动）。约等于常见 fling 判定，
/// 慢速下拉（读歌词）与列表内滚动都不会达到。
static const double _kFlingCloseVelocity = -700.0;
```

### 4.3 `SyncedLyricsView` 接线

```dart
child: AMLLLyricsWidget(
  ...
  onFlingDownClose: widget.onClose,
  enableFlingDownClose: !_isDesktop && !kIsWeb,
  ...
),
```

## 5. 行为与边界

- **触发**：列表滚到顶部后再快速下拉 → 直接关闭（复用 `onClose`，无退场动画）
- **不触发**：慢速下拉（读歌词）、列表中部上下滑（滚动歌词）、桌面/Web（鼠标与触控板无 fling 语义）
- **短歌词列表**（不足一屏）：`maxScrollExtent = 0`，越界照常产生 overscroll 通知，可正常触发
- **重复触发安全**：一次甩动可能产生多次 overscroll 通知，`onClose` 幂等（`_showLyrics` setter 有防重入守卫）
- **关闭副作用**：走 `_showLyrics` setter → 与车载 30s 计时器歌词守卫联动（退出歌词后若播放中则重新计时）
- **内嵌精简歌词**：`CompactLyricsView` 不传新参数，功能关闭，零影响

---

## 6. 调参与验证

**阈值调参**（`_kFlingCloseVelocity` 一处）：偏灵敏 → -800~-900；偏迟钝 → -500~-600。

**自动化：** `flutter analyze` 无新增 error；歌词曲线/车载守卫单测不破坏。

**真机验证清单（移动端）：**
1. 歌词列表中部快速下滑 → 只滚动歌词，不关闭
2. 滚到顶部后再快速下拉 → 关闭歌词回到封面态
3. 顶部慢速下拉 → 不关闭
4. 短歌词（不足一屏）快速下拉 → 关闭
5. 关闭后播放中停留 30s → 车载倒计时正常恢复（与歌词守卫联动）
6. 桌面端快速滚轮/触控板 → 不误关

---

## 7. 风险与回滚

| 风险 | 应对 |
|---|---|
| 阈值手感不合适 | 单点常量调整（§6），不涉及逻辑 |
| 个别设备 overscroll 通知异常 | 观察类实现，无副作用；最坏情况是功能不触发，可整体关闭（`enableFlingDownClose` 置 false） |

**回滚：** 全部改动集中在 `synced_lyrics_view.dart`（可选参数 + 一个通知分支 + 一处接线），git 单 commit 可整体回退。
