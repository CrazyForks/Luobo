# Luobo 性能监控与日志系统技术文档

> 状态：仅设计（2026-08-03）
> 范围：统一日志体系、全局异常捕获、性能指标采集、场景化埋点（播放中断无声 / 全屏车载页卡顿 / 网络切换转码）
> 设计约束：**纯本地、不上报**（隐私优先），数据只存设备；对外唯一出口为手动导出日志文件。开发基于本设计文档进行，实施进度回写本表。
> 实施进度：⬜ 未开始。

## 1. 背景与目标

当前痛点：

- 全项目约 465 处散落 `debugPrint`，靠手写前缀（`[Auth]`、`[Musly]`、`UPnP:`）区分；无级别、无统一格式、release 下零输出，线上排查只能靠猜；
- 无任何全局异常捕获（无 `runZonedGuarded` / `FlutterError.onError`），未捕获异常直接走 Flutter 默认行为；Countly `recordError()`（`analytics_service.dart:248`）定义后从未被调用；
- 已复现但无法定位的问题：电话/蓝牙中断后"点继续播放无声"、全屏页/车载页切换间歇卡顿、WiFi/移动网切换时的转码问题；
- 性能数据是"点状"的（Dio 拦截器计时、缓存用量），无汇聚、无帧率/启动/播放质量指标。

目标：

- 建立**统一本地日志体系**（全模式生效，含滚动文件），替换散落 debugPrint；
- 三路**全局异常捕获**，错误带堆栈落入日志；
- **性能指标采集**（帧率/启动/网络/内存），成本可控（平时无感、卡顿才触发深录）；
- **场景化埋点**以"会话时间线"形式还原问题现场：播放中断无声、页面卡顿、网络切换转码；
- 诊断页查看与导出，帮助排查。

## 3. 架构总览（本地优先，三层）

```
采集层 Collect          处理层 Aggregate             消费层 Consume
┌──────────────┐      ┌───────────────────┐      ┌──────────────────┐
│ Logger API   │      │ DiagnosticsService│      │ 诊断页（设置内）   │
│ 全局异常钩子  │ ───► │ 事件环形缓冲(500)  │ ───► │ 日志查看/过滤      │
│ Dio拦截器    │      │ 会话时间线聚合      │      │ 指标卡片(FPS等)    │
│ FrameTimings│      │ 60s 指标快照 JSON  │      │ 按 sessionId 回放  │
│ 场景埋点     │      │ 事件/快照文件      │      │ 导出日志文件        │
│ 派生检测器   │      │ (events/metrics)  │      │                    │
└──────────────┘      │ 轮转与保留(5×1MB)  │      └──────────────────┘
                     └───────────────────┘
```

设计原则：

- **本地优先**：所有事件只写本地（内存环形缓冲 + 滚动日志文件），不发起任何网络上报；
- **零损耗常态**：常开埋点成本每帧几 µs；深录（Timeline trace）只在检测到卡顿后触发 1~2s；
- **时间线可回放**：所有事件带 sessionId 与全局序号，一次问题 = 一条可读时间线。

## 4. 核心机制：事件与会话时间线

### 4.1 事件模型

```
DiagnosticEvent {
  ts:           DateTime（本地毫秒）
  seq:          int（全局递增序号，用于排序）
  sessionId:    String（主会话 ID：播放相关=PlaybackSession，网络相关=NetSession，其余=AppSession）
  appSessionId: String（必带，见 4.2）
  netSessionId: String?（网络相关事件携带）
  type:         String（如 audio.interruption / frame.jank）
  level:        debug|info|warn|error
  payload:      Map<String, dynamic>（结构化为 JSON 落盘）
}
```

示例（单行 JSON）：

```json
{"seq":1234,"ts":"2026-08-03T21:03:45.123","sessionId":"ps-8f3a","appSessionId":"as-01","type":"log.info","level":"info","payload":{"tag":"Player","file":"player_provider.dart","line":1934,"msg":"play()","trigger":"user","sessionActive":false}}
```

事件 `type` 命名采用 `domain.action`（如 `audio.interruption`、`net.switch`），开发时维护**常量表**（如 `lib/services/diagnostics/event_types.dart`），避免字符串拼写漂移。

### 4.2 会话 ID

- **PlaybackSession**：一次播放会话（开始播放 → 切歌/停止/App 退出），播放相关事件共享；
- **NetSession**：网络状态段（每次 `net.switch` 切段）；
- **AppSession**：一次 App 运行（启动 → 退出），全局日志按此归档。

### 4.3 存储与导出策略

**增量追加，跨冷启动保留，不清空。**

- 事件文件 `events.jsonl`：append 模式，冷启动不删旧内容；每次启动靠 `appSessionId` + 「启动里程碑」事件分段，时间线可跨启动回放；
- 轮转：单文件满 1MB 切新文件，最多 5 个，删最旧 → 始终保留"最近约 5MB"，覆盖崩溃前最后几次启动；
- 崩溃不丢数据：事件**实时异步落盘**（批量 flush，如 200ms 一次），进程被杀/崩溃时最后事件已在磁盘；
- 内存环形缓冲（500 条）仅为诊断页实时查看视图，**不影响落盘完整性**（落盘全量，不截断）；
- 指标快照 `metrics.jsonl`：60s 一条，增量追加，独立保留（如最近 24h）；
- `seq` 全局递增需**跨启动持久化**（启动时从文件尾或 SharedPreferences 恢复），保证时间线顺序不重号；
- **Web 平台降级**：无文件系统，事件仅存内存环形缓冲 + console，导出走浏览器下载（Blob/File API），`metrics.jsonl` 同；
- **isolate 边界**：事件仅在 UI isolate 产生与落盘；其他 isolate（如 BPM 分析）如需记录，通过 `SendPort` 转发到 UI isolate 统一落盘。

导出 = `diagnostics/` 目录打包：`events.jsonl`（全部事件+日志+异常堆栈）+ `metrics.jsonl` + `meta.json`（版本/设备/启动次数）+ 自动生成的可读文本 `export.txt`（时间线格式）。移动端走系统分享/存文件，桌面端存用户目录。

### 4.4 容量预算（1h/天 场景）

- 事件格式：紧凑 JSON 单行，平均 ~250B/条；
- 逐条落盘（日志 + 播放/导航/埋点事件）：~1400 条/h ≈ 350KB/h；
- 聚合摘要（帧率/网络耗时，60s 一条）：60 条/h ≈ 18KB/h；
- **合计 ≈ 0.37MB/h → 1h/天 ≈ 2.6~3MB/周**，5MB 轮转窗口覆盖约 1.5~2 周；
- **红线**：帧级/请求级数据只聚合、不逐条落盘（逐帧落盘 ≈54MB/h 不可接受）；release 默认 info 级，debug 级不落盘；轮转上限兜底。

### 4.5 派生检测器（后台自动生成"结论事件"）

| 检测器 | 判定规则 | 产出事件 |
|---|---|---|
| silentPlayback | play 后 1~2s 内 `processingState==playing` 但 position 未前进 | `audio.silentPlayback` |
| stall | buffering 中 position 停滞超阈值（如 3s） | `audio.stall` |
| frame.jank | 单帧 build+raster 耗时 >50ms | `frame.jank`（带路由/交互上下文） |
| cacheConflict | prune 删除了当前正在播放的流文件 | `cache.prune` + conflict 标记 |

## 5. 模块设计

### 5.1 LoggingService（`lib/services/logging_service.dart`，新增）

- 级别：debug / info / warn / error；
- 格式：`[时间][级别][Tag][file:line] message`；
- 双 sink：
  - console：仅 debug 模式（替换 debugPrint）；
  - 事件流：**全模式生效**，日志作为 `log.*` 类型事件**产出并转发 DiagnosticsService**（见 5.4）统一落盘/轮转/导出；LoggingService 本身不直接写文件；
- 敏感信息：日志统一复用 `_sanitizeUrl` 打码逻辑（`subsonic_service.dart:43-54`），不落密码/token；
- 建议基于 Dart 官方 `logging` 包（零传递依赖），包一层静态 API：`Log.i('Auth', '...', error: e)`；
- 懒格式化：仅在级别开启时拼接字符串，避免热路径成本；
- 初始化时序：**全局静态实例，`main()` 首行即可调用**；未落盘前事件先入内存队列，DiagnosticsService 初始化后统一 flush 落盘（保证启动早期日志与首个里程碑不丢）；
- 异常堆栈中的 URL 同样走 `_sanitizeUrl` 脱敏后落盘。

### 5.2 GlobalErrorHandler（`lib/services/global_error_handler.dart`，新增）

- 三路挂钩，全部落入日志（error 级，带堆栈）：
  - `runZonedGuarded` 包裹 `runApp`（`main.dart:262`）；
  - `FlutterError.onError`；
  - `PlatformDispatcher.instance.onError`；
- 记录未捕获异常后**触发一次立即 flush**（同步落盘该事件），避免进程即将终止时最后一条丢失；
- `ErrorWidget.builder` 显示友好错误页 + 错误摘要（不影响崩溃信息落盘）；
- 本设计不含崩溃上报（纯本地）；Countly 现有崩溃上报维持原样，不动。

### 5.3 MetricsCollector（`lib/services/metrics_collector.dart`，新增）

| 指标 | 机制 | 成本 | 生效模式 |
|---|---|---|---|
| 帧摘要 | `SchedulerBinding.addTimingsCallback` → build/raster 耗时入**帧数据环形缓冲（最近 10s，供派生检测器消费）** | 每帧几 µs | 所有模式 |
| 长帧深录 | jank 触发 → 开启 `dart:developer` Timeline 录制 1~2s → 关闭落盘 | 仅录制窗口 | profile |
| 页面 build 计时 | 主要页面 build 内 Stopwatch 打点，>16ms 记 `screen.buildTime` | 每 build 几 µs | 所有模式 |
| 启动里程碑 | `main()` 各阶段打点：引擎初始化 → 服务初始化 → 音频引擎 → runApp → 首帧 | 一次性 | 所有模式 |
| 网络 | 扩展现有 Dio 拦截器（`subsonic_service.dart:56-84`），**同时挂到 JellyfinService 的 Dio**（`jellyfin_service.dart:39-42`），歌词服务请求后续接入：耗时/状态码/失败率/超时重试 | 已有 | 所有模式 |
| 内存/缓存 | 原生端（`dart:io` `ProcessInfo.currentRss`，Web 跳过）；图片缓存张数/MB；流媒体缓存磁盘占用 | 低频采样 | 所有模式 |

### 5.4 DiagnosticsService（`lib/services/diagnostics_service.dart`，新增）

- 事件环形缓冲（最近 500 条，实时查看视图）+ 60s 指标快照 JSON；
- **唯一落盘者**：负责事件/快照的落盘、轮转、`seq` 分配与持久化、导出；LoggingService 与各埋点只产出事件，不直接写文件；
- 会话时间线聚合：按 sessionId 将事件串成时间线，供诊断页回放；
- 事件/快照文件落盘与轮转、导出（见 4.3）；
- 导出：日志文件 + 快照 JSON 打包，移动端走系统分享/存文件，桌面端存用户目录，Web 走浏览器下载；
- 初始化于 `main.dart` 服务创建段（约 `:161-171`），全局单例；启动里程碑需在初始化前内存暂存、初始化后补录（见 5.3）。

### 5.5 诊断页（`lib/screens/` 新增设置 tab）

- 日志查看：级别过滤、搜索、按 session 回放时间线；
- 指标卡片：FPS、jank 率、网络 p90 耗时、冷启动时长、缓存占用；
- 导出按钮、清空日志（手动操作，**仅建议导出后清空**，避免清掉未导出的崩溃现场）。

## 6. 场景埋点清单

> 约定：所有事件自动携带当前 `sessionId`（播放/网络/App 主会话，见 4.2）、必带 `appSessionId`，网络相关事件另带 `netSessionId`。挂钩点均为现有代码位置。

### 6.1 场景 A：电话/蓝牙中断后"点继续播放无声"

根因假设（探索结论）：`_configureAudioSession()`（`player_provider.dart:1349-1390`）在打断/断开时仅 pause；再次 `play()`（`:1934-1964`）只走 `_ensureAudioFocus()`，**Android 无 `session.setActive(true)`**，且全项目无路由切换处理 → 状态 playing 但音频未激活/未路由。

| 事件 | 挂钩点 | 关键字段 |
|---|---|---|
| `audio.interruption` | `player_provider.dart:1357` | begin/end、type(duck/pause/unknown) |
| `audio.noisy`（设备断开） | `player_provider.dart:1383` | 设备类型 |
| `audio.routeChanged` | 新增（audio_session 无 route 流，用 `becomingNoisy` + 播放时 `getDevices()` 快照对比实现） | from→to 设备 |
| `player.action` | `play():1934` / `pause():1966` / `togglePlayPause():2107` | trigger(user/callback/interruption/noisy)、sessionActiveBefore、routeBefore |
| `audio.sessionState` 快照 | play() 入口 | sessionActive、route、interruptionInProgress、playing、processingState |
| `audio.silentPlayback`（派生） | 检测器 | causeSeq（触发前最近关键事件 seq，便于回放） |

### 6.2 场景 B：全屏页/车载页切换间歇性卡顿

重活点：进全屏页调色板提取（`now_playing_screen.dart:1107-1168`，首次需下载图片，`_paletteCache` 上限 20 条 `:1097`）；封面双图加载（`:2046-2068`）；旋转/脉冲双常驻动画（`:1944-1966`）；车载页 initState 拉歌词+收藏（`car_mode_screen.dart:75-101`）；进页动画（`main_screen.dart:310-347` 上滑 400ms、`now_playing_screen.dart:2493-2506` 进车载 Fade 200ms）。

| 事件 | 挂钩点 | 关键字段 |
|---|---|---|
| `nav.transition` | `main_screen.dart:310`、`now_playing_screen.dart:2493` | from、to、transitionMs、期间 jank 帧数 |

### 6.3 场景 C：WiFi/移动网切换时的转码问题

代码路径：转码参数在播放开始时定死（`player_provider.dart:1697-1705` 生成带 maxBitRate 的流 URL）；网络切换只改 `_currentConnectionType`（`transcoding_service.dart:123-136`，仅 smartEnabled 时监听）；`resolveActiveUrl()`（`subsonic_service.dart:112-144`）切 base URL——已开始的流 URL 不变，切换后旧地址可能不可达。

| 事件 | 挂钩点 | 关键字段 |
|---|---|---|
| `net.switch` | `transcoding_service.dart:128` + `auth_provider.dart:41` | from→to、smartEnabled、切换前后 bitrate |
| `net.urlResolved` | `resolveActiveUrl()` | 探测 host、延迟、是否切换 |
| `stream.url` | `getStreamUrl`（`subsonic_service.dart:478`）+ `_setActiveStream`（`player_provider.dart:988`） | urlHost、maxBitRate、format、是否转码 |
| `audio.bufferStart/End` | just_audio bufferEvent | 时长、urlHost、netType |
| `audio.stall`（派生） | 检测器 | 停滞时长、网络状态、是否转码流 |
| `audio.error` | `_playerStateSub`（`player_provider.dart:1223`） | 错误类型、urlHost、netType、isTranscoded |

### 6.5 明确不采集

URL 中的密码/token（打码）、歌词内容、歌单明细、用户身份信息。日志只记"发生了什么、耗时多少、错误码"及排查必需的资源 ID（songId/URL host），**不记标题/歌词等文本内容**。

## 7. 性能损耗说明（三层设计）

| 层 | 机制 | 成本 | 生效模式 |

## 8. 分阶段实施计划
