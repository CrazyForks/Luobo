# Luobo 音乐库刷新功能改造技术方案

> 状态：已实施 v1.3（2026-08-05，待真机验证）
> 范围：音乐库顶部刷新按钮 + 首页 3 处同源刷新入口（`home_screen` / `home_v2_screen`）的"刷新无感知"问题。核心是给 `LibraryProvider.refresh()` 加**可观测的刷新状态机**，配套按钮 loading、完成/失败提示，并修复显式刷新可能触发两次全量同步的缺陷。纯客户端改造，**不动数据存储结构 / 推荐引擎 / 服务端协议**
> 设计约束：`refresh()` 有 4 处调用方（1 处 await、3 处 fire-and-forget），API 语义改动必须全部兼容；全量同步仍是后台任务，不阻塞 UI；本地模式刷新语义不改变（重读不重扫）；与「音乐库四 Tab 平级横滑技术方案」只重叠文件、不重叠改动
> 实施进度：✅ 已实施（2026-08-05，`flutter analyze` 改动文件零告警、`diagnostics_store_test` 5/5 通过），待真机验证

## 1. 背景与目标

### 1.1 用户反馈的痛点

点音乐库顶部刷新按钮"看起来没反应"：
1. 按钮点击后**无任何视觉反馈**（不转圈、无提示），全量同步在后台静默进行
2. 曲库大时全量同步要几十秒，期间界面毫无变化，用户无法判断"点了有没有用"
3. 同步进行中再点按钮被 `_isRefreshing` 静默忽略，无任何提示

### 1.2 代码实证的根因

| 根因 | 证据 | 本次是否解决 |
|---|---|---|
| `refresh()` 是无状态 fire-and-forget，UI 拿不到"进行中/完成/失败" | `library_provider.dart:845-855`，`_refreshAllDataInBackground`（`:573-669`）只在结尾 `debugPrint`，失败也仅 `debugPrint`（`:664-668`） | ✅ Provider 加状态机 + 返回 `RefreshResult` |
| 刷新按钮不渲染任何加载态 | `library_screen.dart:139-151`，固定 `CupertinoIcons.refresh` 图标，`onPressed` 不 await | ✅ 按钮按状态切转圈 + 居中 toast |
| 显式刷新可能触发**两次全量同步** | `refresh()` 先 `initialize(force:true)` → 内部 `_scheduleBackgroundRefresh()`（`:557-569`，因 `_lastCacheUpdate=null` 判定过期）排 5s 后全量；紧接着 `refresh()` 又立即调一次全量（`:853`）。小曲库 5s 内同步完则第二发重复跑 | ✅ 显式刷新关闭后台调度，统一由 `refresh()` 管理 |
| 同步中重复点击静默忽略 | `_refreshAllDataInBackground` 开头 `if (_isRefreshing) return;`（`:574`） | ✅ 改为合并：重复点击返回同一任务的 Future，并可提示"正在同步" |
| 失败无感知 | 全量同步异常只进 catch 打日志，UI 无任何提示 | ✅ 失败 居中 toast 报错 |
| 首页 3 处刷新入口同样无反馈 | `home_screen.dart:660`、`home_v2_screen.dart:609`（错误态按钮）、`home_v2_screen.dart:64`（`_handleRefresh` await 但丢弃结果） | ✅ 统一受益于状态机 + 居中 toast |

### 1.3 目标

- **感知**：点刷新 → 按钮转圈 → 完成弹"刷新完成：N 张专辑 · M 首歌曲" / 失败弹"刷新失败"；同步中再点不重复启动、有提示
- **正确性**：显式刷新不再产生重复全量同步；后台刷新 / 首启自动刷新 / 显式刷新三者防重入共用一套锁
- **兼容**：`refresh()` 返回值 `void → Future<RefreshResult>`，4 处调用方零破坏（不 await 也合法）
- **本地模式**：刷新语义不变（重读本地扫描结果并提示），不触发重扫（重扫有独立入口，见 §6 待确认）

```

### 2.2 `refresh()` 现状执行序列（`library_provider.dart:845-855`）

```
refresh()
├─ _lastCacheUpdate = null                    // 强制过期
├─ await initialize(force: true)
│   ├─ 重读 SharedPreferences/SQLite 缓存
│   ├─ 拉 recent / random / playlists / artists（5s 超时，失败静默）
│   └─ _scheduleBackgroundRefresh()           // ← 因 lastCacheUpdate==null 排 5s 后全量 ⚠️
└─ if (!offline && !localOnly) _refreshAllDataInBackground()   // 立即全量 ⚠️

- ✅ `getMusicFolders()`（`:480`）——轻量连通性探测可用
- ⬜ 未实现 `getScanStatus` / `startScan`（Navidrome 支持）——P1 可选增量刷新用

## 3. 方案设计

### 3.1 Provider：刷新状态机（`library_provider.dart`）

新增状态与结果类型：

```dart
enum RefreshStatus { idle, running }

class RefreshResult {
  final bool success;
  final bool merged;      // 本次点击合并进了已在进行的刷新
  final bool isLocal;     // 本地模式重读结果
  final int albumCount;   // 全量同步完成的专辑数（非本地模式）
  final int songCount;
  final String? error;    // success == false 时的原因
}

RefreshStatus get refreshStatus;      // UI 订阅驱动按钮 loading
Future<RefreshResult> refresh();      // 原 void refresh() 改造
```

`refresh()` 改造要点：

```dart
Future<RefreshResult> refresh() async {
  if (_isRefreshing) {
    // 合并：返回进行中任务的同一 Future，不重复启动
    return _activeRefreshCompleter!.future;
  }
  _lastCacheUpdate = null;
  final completer = Completer<RefreshResult>();
  _activeRefreshCompleter = completer;
  _refreshStatus = RefreshStatus.running;
  notifyListeners();
  try {
    await initialize(force: true, scheduleBackground: false); // 修复点①：不排 5s 全量
    final result = await _refreshAllDataInBackground();        // 修复点②：返回结果
    completer.complete(result);
  } catch (e) {
    completer.complete(RefreshResult(success: false, error: e.toString()));
  } finally {
    _refreshStatus = RefreshStatus.idle;
    _activeRefreshCompleter = null;
    notifyListeners();
  }
  return completer.future;
}
```

配套改动：

| 方法 | 改动 |
|---|---|
| `initialize({bool force, bool scheduleBackground = true})` | 新增参数；`refresh()` 传 `false`，首启/常规路径保持 `true`（修复重复调度） |
| `_refreshAllDataInBackground()` | 去掉开头 `if (_isRefreshing) return;`（防重入上移到 `refresh()`）；返回 `RefreshResult`；成功带 album/song 计数（`allAlbums.length` / `_cachedAllSongs.length` 已有）；catch 分支同样返回失败结果 |
| `_scheduleBackgroundRefresh()` | 不变（只服务首启/6h 过期自动刷新） |

### 3.2 音乐库按钮：按状态渲染 + 结果提示（`library_screen.dart:138-151`）

```dart
Consumer<LibraryProvider>(builder: (context, lp, _) {
  final running = lp.refreshStatus == RefreshStatus.running;
  return IconButton(
    icon: running
        ? const SizedBox(
            width: 18, height: 18,
            child: CircularProgressIndicator(strokeWidth: 2))
        : const Icon(CupertinoIcons.refresh),
    tooltip: l10n.refresh,
    onPressed: () => _handleRefresh(context),
  );
})
```

`_handleRefresh` 统一 await + 居中 toast：

| 结果 | 提示 |
|---|---|
| `success && merged` | 不弹（转圈已表达"正在同步"）或短提示"正在同步" |
| `success && !merged && !isLocal` | "刷新完成：N 张专辑 · M 首歌曲" |
| `success && isLocal` | "已重新加载本地音乐库" |
| `!success` | "刷新失败，请检查服务器连接" |

居中 toast 文案走 l10n（§5）。

> 实现说明（v1.3）：提示用**原生 `SnackBar`（`behavior: floating`）+ `margin` 垂直居中**（`margin.bottom = 屏高/2 − 28`），完整保留 SnackBar 观感与行为（主题样式、滑动关闭、消息队列），统一封装在 `lib/utils/refresh_feedback.dart` 的 `showCenteredToast`；连续刷新用 `removeCurrentSnackBar()` 替换而非排队。未引入第三方 toast 库（`fluttertoast` 等，评估后不必要）。

### 3.3 首页 3 处入口统一

- `home_v2_screen.dart:59-65` `_handleRefresh`：改为 `final r = await libraryProvider.refresh();` 按结果弹提示（下拉刷新完成也可静默，待确认）
- `home_v2_screen.dart:606-609`、`home_screen.dart:660` 错误态按钮：`onPressed` 改调用同一 `_handleRefresh`/等价逻辑，刷新中按钮禁用并显示转圈

### 3.4 本地模式语义（不变 + 可感知）

`refresh()` 本地分支（`initialize` 内 `_localOnlyMode` 路径）保持重读 `_localMusicService` 数据，但返回 `RefreshResult(isLocal: true)`，UI 提示"已重新加载本地音乐库"。**不**在本次方案内把刷新按钮改为触发重扫（重扫走空态"扫描音乐"入口）。

## 4. 数据流时序（改造后，服务器模式）

```
用户点音乐库刷新按钮
└─ _handleRefresh
   ├─ refreshStatus == running? ── 否 ──► refresh()
   │                                   ├─ _isRefreshing? ── 是 ──► 返回进行中 Future（merged=true）
   │                                   ├─ status=running → notifyListeners → 按钮转圈
   │                                   ├─ initialize(force, scheduleBackground:false)
   │                                   │    └─ 重读缓存 + 拉小列表（recent/random/playlists/artists）
   │                                   ├─ _refreshAllDataInBackground()（返回结果）
   │                                   │    └─ 清库 → 分页拉专辑 → 并发拉歌曲 → 更新缓存 → notifyListeners
   │                                   ├─ status=idle → notifyListeners → 按钮复原
   │                                   └─ 返回 RefreshResult
   └─ 居中 toast：完成数字 / 失败原因
```

- 重复点击：转圈保持，`merged=true`，只跑一次全量（logcat 只见一条 `Background refresh complete`）
- 断网：小列表 5s 超时 → 全量异常 → 返回失败 → 居中 toast 报错
